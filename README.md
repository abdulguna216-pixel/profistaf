# ПРОФИ·СТАФФ

Адаптивный одностраничный сайт по `PROFI_STAFF_site_prompt.md` и приложенному изображению 1024 × 1536 px. React 19 + Vite 7, обычный CSS, локальные шрифты и оригинальные изображения WebP. Исходный референс в родительской папке сохранён без изменений.

## Запуск

Нужен Node.js 22.12+ с npm. В рабочем окружении Codex использован встроенный Node.js 24 и pnpm, поскольку системные `node` и `npm` отсутствуют в PATH.

```sh
cd "/Users/abdul/Desktop/профистаф/site"
npm install
npm run dev
```

Vite выведет локальный адрес, обычно `http://127.0.0.1:5173`.

```sh
npm run build
npm run preview
```

Готовые статические файлы находятся в `dist/`. Для другого компьютера достаточно исходников, каталога `public/` и установки зависимостей. Все шрифты и фото обслуживаются локально; сайт не обращается к Google Fonts.

Альтернативный воспроизводимый запуск: `pnpm install --frozen-lockfile`, `pnpm dev`, `pnpm build`.

## Реализовано

- Структура из восьми частей: шапка, hero, услуги, процесс, преимущества, FAQ, форма, подвал.
- Три строки заголовка hero на desktop; четыре управляемые строки на mobile.
- Сетки услуг: 4 колонки на desktop, 2 на tablet, 1 на узком mobile.
- Рабочие якоря, мобильное меню с Escape, возврат наверх.
- Стрелки услуг переключают направление и фокусируют соответствующую карточку. Кнопка карточки выбирает тип задачи и переводит к форме.
- Пять раскрывающихся FAQ с `aria-expanded`, `aria-controls`, управлением Enter/Space.
- Валидация имени, телефона, направления и чекбокса. Доступные ошибки, состояние отправки, блокировка повторного submit, обработка ошибок сервера.
- Активация этапов по скроллу, раскрытие карточек и преимуществ через оригинальный движок Scroll Craft. Без pinning и дополнительных экранов.
- Локальные Oswald Bold с кириллицей и Manrope Variable, лицензии SIL OFL приложены. Горизонтальное сжатие заголовков настроено по референсу.
- Пять оригинальных фотографических ассетов. Фото иллюстрируют направления, не являются документальными снимками сотрудников компании. Два размера каждого WebP, `srcset`, lazy-loading за пределами hero, заданные размеры изображений.
- Собственные растровые halftone-ассеты с переменным размером точек, SVG-иконки, reduced-motion, видимый клавиатурный фокус, skip-link.

## Форма и данные, которые необходимо предоставить

По умолчанию включён **демонстрационный режим**. Введённые значения проверяются только в браузере; заявка не отправляется, данные не сохраняются. При корректном заполнении показано именно это сообщение. Сайт не имитирует реальную доставку.

Перед рабочим запуском нужно:

1. Предоставить реальный сервер приёма заявок или настройки Telegram-интеграции. Telegram-токены должны храниться только на сервере.
2. Предоставить утверждённую политику обработки персональных данных и формулировку согласия. Вместо фиктивной политики сейчас открывается уведомление о демонстрационном режиме.
3. Указать реальные телефон, email и необходимые реквизиты компании. В подвале используется обозначенный placeholder «Телефон компании».
4. Подтвердить позиционирование hero, категории услуг, порядок подбора, выхода и контроля сотрудников, коммерческие условия. Сроки, бесплатные замены и специальные гарантии не придуманы; FAQ и описания преимуществ сформулированы нейтрально.

Настройка подключения:

```sh
cp .env.example .env.local
```

Укажите оба параметра:

```dotenv
VITE_LEAD_ENDPOINT=/api/leads
VITE_PRIVACY_URL=/privacy
```

Затем пересоберите сайт. Только при наличии **обоих** параметров форма переходит к реальной отправке. Указанные адреса нужно реализовать на вашем сервере: этот статический проект не создаёт `/api/leads` и `/privacy` автоматически.

Форма отправляет `POST` с `Content-Type: application/json`:

```json
{
  "name": "Имя",
  "phone": "+…",
  "task": "Комплектация",
  "consent": true,
  "website": ""
}
```

Сервер должен повторно валидировать данные, проверять пустоту honeypot-поля `website`, ограничивать частоту запросов и возвращать HTTP 2xx с `{"ok":true}` **только после реального приёма/доставки**. Для ошибки верните соответствующий HTTP-код и `{"ok":false}`. Тайм-аут клиента — 15 секунд. Для внешнего endpoint необходимо настроить CORS. Секреты нельзя помещать в переменные `VITE_*`: они доступны посетителю в клиентском коде.

## Проверки и скриншоты

Проверка в реальном Chromium: 320/375/390/768/1024/1440 px, ordinary/reduced motion. Все размеры без горизонтального переполнения, обрезанных заголовков и отсутствующих фотографий. Функциональные проверки включают мобильное меню, клавиатуру, пять FAQ, четыре направления, стрелки, якоря, поля и согласие. Браузерных ошибок нет.

Отправка проверена отдельным тестовым API-перехватом: payload, блокировка повторного submit, успех при `ok:true`, ошибка HTTP 503 и сохранение полей. Это проверка клиентского контракта, **не проверка реальной доставки**. В деморежиме подтверждено отсутствие POST-запросов. Итоговый отчёт: `docs/qa-report.json`.

- `docs/screenshots/desktop.png` — полная страница при 1024 px.
- `docs/screenshots/mobile.png` — полная страница при 390 px.
- `docs/screenshots/mobile-hero.png` — первый экран mobile.
- `docs/screenshots/width-320.png`, `width-375.png`, `width-768.png`, `width-1440.png` — остальные размеры.
- `docs/screenshots/scroll-frame-*.png` — промежуточные кадры всех разделов.
- `docs/screenshots/scroll-desktop/` — результаты штатной проверки Scroll Craft; dead scroll не обнаружен.

Скриншоты визуально просмотрены и сравнены с исходным изображением. Компромиссы: Oswald является открытой заменой коммерческого шрифта; фотографии оригинальные, поэтому не совпадают попиксельно. Дополнительное уведомление о деморежиме немного увеличивает нижний блок.

На реальном физическом телефоне сайт не проверялся. Автоматизация подтверждает размеры и функциональность в браузере.

## Использованные инструкции

- [Taste Skill](https://github.com/Leonxlnx/taste-skill): изучены `SKILL.md` и руководство по типографике; применены статическая сборка перед motion, две шрифтовые семьи, работа с оригинальными изображениями, оптическая настройка и цикл screenshot → correction. Запущены штатные lint и browser inspect. Аудит не является полностью зелёным: он запрещает предусмотренные заказчиком номера, подписи над заголовками, многострочные заголовки, тонкие разделители и компактный текст. Эти требования не применены там, где противоречат утверждённому макету. Непереопределённый отчёт сохранён в `docs/taste-inspection/report.json`.
- [Scroll Craft](https://github.com/nateherkai/scroll-craft): изучены `SKILL.md`, движок и руководство по visual craft. Оригинальный движок и CSS включены без правок в `src/vendor/`, лицензия MIT приложена. Запущены `doctor.mjs` и `shoot.mjs`; штатная проверка прокрутки выполнена. `doctor` сообщил отсутствие полного ffmpeg; видео не используется, а браузер проверен через имеющийся Chromium. Из-за отсутствия ffmpeg штатный contact sheet не создан; отдельные кадры получены, дополнительная контактная таблица собрана отдельно.
- Hyperframes motion-graphics не запускался: короткий motion-ролик не требуется для этой композиции; его добавление изменило бы утверждённую структуру.
- Sites использован для закрытого предпросмотра; исходники полностью доступны для самостоятельного размещения.

Ограничения доступности самого утверждённого дизайна: мелкие desktop-подписи и белый текст на ярком оранжевом CTA не соответствуют всем требованиям WCAG AA. Проверка измерила около 3.3:1 для CTA. Клавиатура, семантика форм и reduced motion реализованы; полное соответствие WCAG AA не заявляется. При согласовании доступной версии потребуется уточнить цвет CTA и размер мелкого текста.
